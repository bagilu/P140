# P140 V0.008｜GitHub Pages 部署

部署包：P140_GitHubPages_V0.008.zip。解壓後最外層為同名資料夾，裡面的index.html、admin.html、data/、vendor/等可直接放在GitHub專案根目錄，不需要建置工具、Supabase、API金鑰或config.js。

## 上傳與發布

1. 先備份自己瀏覽器中的工作台草稿。
2. 解壓ZIP，把同名資料夾內的全部檔案與資料夾上傳到GitHub專案根目錄，讓index.html位於最上層。保留相對目錄及.nojekyll。
3. 到Settings → Pages，Source選Deploy from a branch，Branch選main（或實際使用的分支），資料夾選/(root)，按Save。
4. 等Pages完成發布，開啟其提供的網站網址；確認左上版本V0.008。若舊頁仍留在快取，可重新整理。

ZIP是根目錄部署版，沒有額外的dist層。來源專案本身仍以dist/存放網站；不要把這兩種目錄結構混在同一個發布根目錄。

## V0.008操作

- 遠景維持公車、實線路徑與接近站點時的名稱。
- 放大至街道尺度（zoom14）顯示可點選站點，滑鼠移過可看站名；更近（zoom16）會在不擠壓車輛標記的空間顯示站名。
- 點選一站，先看時間軸之後最多3班（含當時停靠時段）。同站301與310會一起列出，並標示方向、發車／到站／終點抵達及時間來源。
- 「所選星期全部時刻」預設收合，需要時再展開；不是把全部站點的全天表貼在地圖上。
- 星期及時間軸改變會更新站點卡，且不自動平移或縮放。選站也不改變視角。
- 縮小到遠景（低於zoom14）會收起站點與時刻卡；也可按關閉、點空白地圖或按Escape關閉。
- 24:00起以隔日00:00的排程列出，卡片上有明確說明。跨午夜班次可沿用前一服務日的星期設定。

站點資訊是道路層級概略資料，近距離同名站可共用一張卡；道路兩側的行駛方向以各列目的地辨識。遠距同名站不會只因名稱一樣就合併。

## 更新公車資料

前台仍只讀data/bus_network.json。編輯器可匯出單路JSON，並使用多路線合併功能產生完整路網；將合併結果放回data/bus_network.json，再上傳更新。保留每路原始JSON與來源日期，方便後續維護。

站點時刻表直接由同一份路網推導，不需要另建一份時刻表資料。新增路線後，它的班次會隨新的合併路網一起納入。

## 已驗證與限制

目前只有301與310：100個方向別停靠紀錄合併成48個概略站點群組，所選星期的每日停靠事件共972筆。301來源為業者逐站預估表加動畫平滑；310為使用者提供的模型估算。原始路線JSON未重新估算或改寫。

已驗證同站跨路線合併、星期與跨午夜、近期排序、終點／起點區分、縮放分層與相對路徑。站點全天表不會因播放而反覆重新建立，已展開狀態與捲動可維持。

底圖需要網路。公車位置與到站時間是排程模擬，不是GPS即時車況；有效日期、國定假日、臨時停駛及改道仍應查營運單位公告。既有誤差警語保留。
